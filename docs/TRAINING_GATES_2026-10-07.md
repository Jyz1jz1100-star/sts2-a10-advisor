# 正式训练的放行条件与一个零预算实验的预注册（2026-10-07）

本文回答一个管理问题：**什么时候该投下一笔正式训练预算**。它不是进度记录；每条判据都必须可机检或可用一条命令复算，
不写"感觉稳了"式表述。判据顺序有意义：**前一条不成立就不许花后一条的钱**。

## 0. 触发本文的两条测量

* 40M 步 campaign 臂的优化器全程健康（13,016 次更新、approx_kl 0.0075→0.0098、clip_fraction 0.067–0.089、
  entropy_loss −1.31→−0.61、value_loss 62.2→1.12、explained_variance →0.956），而结果侧 8 个评估点
  `mean_final_floor` 一直平在 7.1–7.9、每检查点 200 局**跨幕次数 0**。所以"梯度炸了"与"算法要重写"都不是结论；
  5 倍预算买来的是记录数，不是方向。
* 训练流里 **80.2% 的步是战斗步**（`docs/evidence/phase_action_share_20261007.json`：60 局 campaign rollout、7,931 步，逐步行按引擎给出的相位归类；幕外合计 **19.8%**，其中 relic_reward 8.0%、map 4.7%、card_reward 2.6%、event 1.6%、ancient 0.76%、shop 1.2%）。
  而产品形态是：真机上打架归第三方 CombatSolver，我们只决策幕外（地图/奖励/事件/篝火/先古）。
  也就是说，按现状再投一笔大预算，买到的主要是**产品不交付的那一层**的技巧。

## 0b. G1 已经落地（2026-10-07 晚），并且是同一份权重的配对复测

改动在 `training/frozen_combat_env.py`：把战斗交给**一份冻结权重**（就是被审计的那个检查点）来打，
agent 只会在幕外相位拿到决策权。同一 60 个种子、同一个检查点、同一 stage 形状重跑审计：
`docs/evidence/phase_action_share_frozen_20261007.json` 里 agent 流的 `combat` 步占比 = **0.0%**、
幕外合计 = **100.0%**，而 `absorbed_combat_steps` = 6,364 —— 与改动前那一份的战斗步数**逐种子相等**，
幕外相位直方图（map 373、relic_reward 635、card_reward 207、event 124、ancient 60、shop 95、rest 36、
transform_select 24、treasure 13）也与改动前完全一致。1,567 + 6,364 = 7,931，一帧没丢。
执行器需要强制叫停的次数 = 0。

**这条改动证明了什么、没证明什么。** 证明的是：战斗确实可以从损失里拿出来而**不改变模拟器轨迹**，
所以 G1 的判据不是靠"少跑了几局"糊过去的。没证明的是：只学这 19.8% 的臂能不能赢——那正是 G4 要判的，
G1 通过本身**不构成投预算的理由**。判据 `trained_actions_are_all_out_of_combat` 已从"声明为红"转为绿，
配对的六条（同种子、同局数、同检查点、旧缺口仍可复算、吸收步数等于旧战斗步数、幕外流未变）在
`phase_action_share` 声明里一起跑，任何一条单独变红都会报出来。

## 1. 放行条件（按序）

**G1 职责对齐。** 训练所更新的动作必须全部属于幕外相位。判据：逐相位审计里 `combat` 步占比 = 0，
幕外相位占比 = 100%，且该审计是产物 + 门禁（不是脚本口口相传）。
代价：工程改动（训练环境里固定战斗执行器），0 训练步。
**状态：判据已达成**（见 0b 的配对复测与 `phase_action_share` 声明）。这一条达成**不构成放行**——
它只把"该不该为幕外决策投钱"变成 G4 能判的问题。附带口径变更：加了执行器的 stage，一步 = 一次幕外决策，
同样的 `timesteps` 会跑出约五倍的局数，所以**跨臂比较只能用等局数，不能用等步数**。

**G2 真机已知阻断解除。** 当前实际安装的 solver 必须从 floor 1、正常取得并使用触发遗物、无中档续档、
无人工救援地通过完整 11 项契约，并在同一已知触发条件上**连续 3 局**通过（这是回归检查，不是可靠性认证）。
代价：0 训练步；外部维护者的等待时间无上限。
已知事实：一幕 9 个具名胜局在 v5 上 0/9 复现；真机在 solver 0.45.0 下有 3 次认证通关，0.50.1 下 0 次，
且存在一条已定位的 mod 侧多选开战页面死锁（重启+续档 4 次同位复现；本方只检测不代点）。

**G3 模拟器基线可信。** 冻结引擎版本、检查点与种子；旧胜局退出正向证据集；每一个有名截断都能逐局归属，
并且至少存在一条**在同一职责约束下**（G1 之后）走完三幕的可复现模拟器轨迹，用来证明训练环境里有成功路径。
代价：0 训练步，1–3 工程天。

**G4 幕外干预确实能改变结果。** 见第 2 节预注册。只有配对改善的 95% CI 下界超过预先写死的 δ 才算过。
代价：0 训练步，约 0.3M 环境步的评估算力。

**G5 小预算证明"可学且能迁移"。** G1–G4 通过后，第一批是**上限 1.5M 步**（40M 的 3.75%）、3 个随机初始化、
只用未参与调参的配对种子；要求三者方向一致、汇总主指标达阈、step_cap 与契约失败不超容忍；
然后用候选与基线在真机配对，沿用原验证器与完整 11 项契约。**必须有真机收益证据**，模拟器成绩与 BC 都不算。
样本不足记"未决"，不得记"通过"。

只有 G5 达标之后才谈"正式训练"（多日、≥500 局真机只是最终验收口径，不是训练手段）。

## 2. G4 预注册（本文档写完即冻结，先看结果再改判据视为无效）

> **一次先于任何结果的更正（2026-10-07 晚，写在第一次查看之前）**：A 臂原写为
> `live_choice_policy`（对**选项文案**打分的规则）。这条在模拟器里**执行不了**，是查出来的不是感觉的：
> `NativeRunCore._info` 只有 12 个数值字段（phase/floor/act/deck_size/gold/player_hp/player_max_hp/
> relic_count/current_node_type/event_id/relic_reward/run_cleared），`state_lists()` 只有 id，
> 整个信息面上**没有任何文案**；而该规则的判据词是简体中文本地化串，即便有英文文案也不是同一条规则。
> 因此 A 臂改为**被冻结检查点自己的幕外决策**（也就是 G5 要花钱去训的东西），B 臂保持
> **合法候选里的最低下标**（本项目出厂时的位置常量）。战斗两臂共用同一份冻结执行器不变。
> **指标、δ、检验、样本量、封存半区一字未改**；改的只是"用什么去代表两种幕外决策"。
> 算力也如实记：注册时估 2,000 次 rollout；实测 campaign 局**每一局都从一幕开场**（60/60 抽样种子
> 开局 act 均为 1，"按种子分配幕"是单幕 stage 的性质），所以 974 个筛查半区种子 × 两臂 = **1,948 次
> rollout**，与注册量级一致 —— 我先前在本文里写的"要跑约 4,000 次"是把这个单幕性质错安到了 campaign 上。

**要判的问题**：把打架固定住，只换幕外决策，一幕结局会不会变？如果不会变，那么幕外策略没有可学的收益空间，
任何预算都不该投。

* **设计**：同种子配对。两个臂共用**同一份冻结权重产生的战斗动作**（战斗执行器完全一致），
  只在幕外相位上分别使用：`A = 现行 live_choice_policy`（`conservative-visible-v2`）、
  `B = 预先固定的幕外基线`（合法候选中的 `index 0`，即旧的位置常量规则）。
  两臂都跑 `campaign=True`、同一 stage 配置、同一地平线。
  （执行器今天已经有了：`training/frozen_combat_env.py` + `config/production_campaign_v5_g1.toml`。
  这条只是把"共用同一份冻结战斗动作"从口头约束变成可以指的东西——**判据、δ、样本量、封存规则一字未改**。）
* **主要指标**：一局是否到达一幕幕王层（floor 17）的二值结果。
  基线值取 v5 全分区实测：309/10,000 = **3.09%**。
  一幕**胜率不作为主要指标**——1/10,000 的稀有事件在可负担样本下没有功效（见第 3 节）。
* **δ（值得投入的最小改善）**：到达率**绝对提升 ≥ +1.5 个百分点**（3.09% → ≥4.6%）。
* **判据**：McNemar 配对检验，**95% CI 下界 > +1.5pp** 才算 G4 通过；
  CI 上界 < 0 → 停止这条干预路线；区间跨过 0 且宽到无法判 → 记"未决"，不得记"通过"。
* **样本量**：设不一致对率约 2.6%（两臂只在边缘局面上分歧），α=0.05 双侧、功效 0.80 下
  n ≈ (1.96+0.84)² × 0.026 / 0.015² ≈ **905 对**，取 **1,000 对 = 2,000 次 rollout**
  ≈ 0.29M 环境步（按 campaign 实测 mean_steps ≈ 145）。
* **保留集**：按种子哈希先把整段分区对半分，**其中一半在任何查看之前封存**；筛查只用另一半，
  封存半区只在最终确认时用一次。种子窗口、哈希规则与分半结果写进产物，不靠约定。
* **不算过关的东西**：训练奖励上涨、平均 HP 更高、到达更多但 CI 不达标、模拟器通关而真机不通。

### G4 执行结果（2026-10-07，产物 `docs/evidence/out_of_combat_screen_20261007.json`，声明 `out_of_combat_screen`）

跑法照注册执行：哈希对半分（筛查半区 974 个种子 / 封存半区 1,026 个**一个没跑**），两臂共用同一份
冻结执行器（检查点摘要一致），1,948 次 rollout，幕外决策分别取"冻结检查点自己的选择"与"合法候选
最低下标"。

| 量 |  trained | positional |
|---|---|---|
| 到达一幕幕王层 (floor 17) | **28 / 974 = 2.87%** | **28 / 974 = 2.87%** |
| 一幕平均到达层 | 7.59 | 7.37 |
| 进入第二幕 | 0 | 0 |
| 通关 / 获胜 | 0 / 0 | 0 / 0 |

配对：不一致 48 对，其中 **trained 独占 24、positional 独占 24** —— 净差 **0.0000 pp**，
95% CI **[−1.394, +1.394] pp**。

**按注册的三分法，结论是"未决"**（区间跨过 0，既不达 δ 也没有整体为负）。但这份数据还说了另一件更硬的
事实：**CI 上界 +1.394pp 落在 δ = +1.5pp 之下**，也就是说注册想要的那个改善幅度，在 95% 置信下**被排除**
了 —— 不是"没测到"，是"就算把运气都算上也不在那儿"。

**据此的管理结论**：G5 不被本筛查授权。"什么时候上正式训练"的当前答案是**不是现在**，理由是量出来的：
把打架固定住之后，现有这套幕外决策与"永远选第一个"在一幕推进上**没有任何可测差别**（2.87% 对 2.87%，
974 对配对）。在这种状态下投多日预算，买到的会是第 0 节已经看过的那种东西——漂亮的价值曲线，和平的深度线。

**这份结果没有说的事**（别把它读成这些）：
① 它没有说"幕外决策不重要"。它说的是**这两种幕外决策之间**没有差别；两臂都在 floor 5–8 大量阵亡，
真正吃掉局数的是战斗结果与消耗，而那归第三方 solver。② 它没有说 RL 学不到东西 —— 它说的是在
"以一幕到达率为信号、战斗固定"的设置下没有可检出的改善空间。③ 平均到达层 trained 7.59 vs positional 7.37
是我**看过结果之后**才看到的量，按本文自己的冻结规则**不能**拿来当判据，只作为观察记录。
④ 封存半区仍是干净的，但按注册它只属于"本筛查的最终确认"，不能被挪去救一个失败的判据。

**下一步该问的问题**（不属于 G4，需要在做完之后另立预注册）：既然产品形态里打架归 solver，那么价值
可能集中在**让 solver 打得更好/更稳**（真机侧：#44 的静默弹窗恢复、G2 的连续三局），
以及**三幕走通之后的幕间资源决策**——后者在当前模拟器里到不了（0/1,948 进第二幕）。

## 3. 为什么一幕胜率不能当训练信号

一幕到达率 3.09% × 到达后转化 1/309 ≈ **每 10,000 局 1 次成功**（v5 实测 1/10,000）。
40M 步 ÷ 145 步/局 ≈ 27.6 万局 → 整轮**期望 27 次成功**，摊到 13,016 次更新 × 12 并行环境，
单批成功样本占比约 10⁻⁴。这正好解释已观测到的形状：价值函数几乎完美（EV 0.956）地拟合了
早期密集奖励，深度曲线全平。所以这不是超参问题：**以胜率为唯一稀疏奖励的幕级 RL，在当前转化密度下没有可用梯度**。

G2 的那条 mod 侧死锁不在我们权限内（不打补丁、不禁用、不重钉，也不代点战斗内页面）；
可转交的复现包在 `docs/COMBATSOLVER_MULTISELECT_BUG_2026-10-07.md`。
G1/G3/G4 与它无依赖关系，可以先做——这也是"全做"的执行顺序。
